# F3 — Limit location, rotation, and scale

Points: 2. Epic F. Depends on [F2](f2.md).

Blender spec: `CONSTRAINT_TYPE_LOCLIMIT`, `ROTLIMIT`, `SIZELIMIT`.

## What to do

Add three constraints that clamp the transform after the copy constraints, in stack order. Each axis has a minimum, a maximum, and a bool that turns the clamp on. Influence blends between the unclamped and the clamped value.

## How to do

1. Payload per type: for each of X, Y, Z, `bool use`, `float min`, `float max`. Defaults: use off, min `-1`, max `1`, so adding the constraint does not pop the object until an axis is enabled.
2. Location and scale: clamp the component, then `lerp(unclamped, clamped, influence)`.
3. Rotation: convert the quaternion to XYZ Euler, clamp the enabled angles in radians, convert back, slerp by influence. This has the usual Euler flip near 180 degrees. Document it on the row as XYZ Euler limits, which is what Blender does.
4. The Constraints tab shows the six numbers and three checkboxes for the active limit constraint.
5. Limits run in the same walker as [F2](f2.md). No second pass.

## What to consider

- Min greater than max is a user error. Swap them when the row is evaluated, or reject the edit. Swapping silently hides the mistake. Reject the edit and keep the previous values.
- Limits are in the owner's local channels after the parent and earlier constraints, not in world space, unless you document world space and test it. Blender's default owner space is world for limit location. Pick world space to match that default and state it in the panel ("World").
- Do not use limits to fake a collision floor. The floor constraint is out of scope ([F4](f4.md)).

## Output

A location limit with Y min `0` and influence `1` keeps the object from going below the ground when the user drags it. Influence `0` lets it through. A bad min/max does not stick. Undo restores the previous limits.
