# F1 — Constraint stack header

Points: 2. Epic F. Depends on [A3](../epica/a3.md) and the Constraints tab from [C3](../epicc/c3.md).

Blender spec: `bConstraint` in `DNA_constraint_types.h`. Fields that matter first: type, name, mute, influence, target.

## What to do

Each object has an ordered constraint list with type, name, mute, influence, and a target object id. The user can add, remove, and reorder. Nothing solves yet. The evaluator from [D1](../epicd/d1.md) calls an empty function per row.

## How to do

1. `ConstraintHeader` in `src/core/`: `uint32_t id`, `name`, `ConstraintType type`, `bool mute`, `float influence` (0 to 1), `uint32_t target_id` (0 means none).
2. `ConstraintType` starts with `None`, `ChildOf`, `CopyLocation`, `CopyRotation`, `CopyScale`, `LimitLocation`, `LimitRotation`, `LimitScale`. Payloads for those types arrive in [F2](f2.md) and [F3](f3.md). The header can exist with `None`.
3. Constraints tab matches the modifier tab: Add, Remove, Up, Down, mute, influence slider. Influence is clamped to `0..1`.
4. Commands and undo, one step per edit, same pattern as [E1](../epice/e1.md).
5. Target is chosen from a list of other objects. An object cannot target itself. The drop-down excludes self.

## What to consider

- Influence `0` means the constraint is present and does nothing. Mute means the same for evaluation. Keep both. Blender has both.
- These are not rigid-body joints. Do not put Hinge in this enum. Joints are [G7](../epicg/g7.md).
- Target ids must tolerate a deleted target. Evaluation will skip a missing target. Do not crash in the panel. Show "Missing target".

## Output

The Constraints tab adds rows, reorders them, mutes one, sets influence, picks a target, and undoes each edit. The object does not move, because no solver runs.
