# F4 — Constraints that wait

Points: 1. Epic F. Depends on [F3](f3.md).

Blender spec: `CONSTRAINT_TYPE_KINEMATIC`, `SPLINEIK`, `SHRINKWRAP`, `FOLLOWTRACK`, `CAMERASOLVER`, `ARMATURE`.

## What to do

Do not implement IK, spline IK, shrinkwrap, trackers, camera solvers, or the armature constraint. The Add menu does not list them. This file is the record of why, and of what has to exist before any of them starts.

## How to do

1. Keep `ConstraintType` limited to the types from [F1](f1.md), [F2](f2.md), and [F3](f3.md).
2. Before any of the skipped types is added, the scene needs an armature (bones, pose channels) or a curve, plus the depsgraph edges those constraints use. That work is not in the pointed epics.
3. If a file from the future contains an unknown constraint type tag, skip the row and report the type id. Do not fail the whole load ([B2](../epicb/b2.md) unknown-chunk rule).

## What to consider

- IK looks like a small constraint and is an iterative solver with a bone chain. Treating it as another matrix row will not match Blender.
- Shrinkwrap needs a BVH of the target mesh. It is a reasonable later constraint once meshes and the collision mesh from [E4](../epice/e4.md) exist. It is still not in this path.
- Do not add a "Floor" constraint as a stand-in for IK. Limits cover the simple case.

## Output

The Add menu shows only Child Of, Copy Location, Copy Rotation, Copy Scale, and the three limits. A reader of this file knows the skipped types and the data they would require.
