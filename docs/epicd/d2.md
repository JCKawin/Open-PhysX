# D2 — Commands and the published snapshot

Points: 3. Epic D. Depends on [D1](d1.md).

Blender spec: the dependency graph is not edited from the draw thread. Operators change original data. Evaluation publishes the result. `hardware.md` calls this the command queue and the snapshot.

## What to do

The UI does not write solver memory and does not write the evaluated mesh. It pushes commands. At the start of a step, the simulation drains the queue onto the authored scene, evaluates, and publishes a snapshot the renderer and the properties panel can read. Until a second thread exists, the queue can be drained on the main thread. The API stays the same.

## How to do

1. `src/logic/Command.h`: `SetTransform`, `SetSelection`, `AddObject`, `DeleteObject`, `SetProperty` for the small set of fields the panels edit. Each command is a plain struct with the object id.
2. `ISimulation::push(Command)` is the only write from `ui/`. `Editor` and `Workspace` stop reaching into `state().cube` and the scene vectors. Reads of the authored scene for the Object tab may stay direct until you switch the panel to the snapshot. Prefer the snapshot for anything that physics will overwrite.
3. `step()` and a new `evaluate_for_draw()` drain the queue, run [D1](d1.md), and swap the published snapshot. Swap is a pointer or an index flip between two buffers, not a copy of every triangle if the mesh did not change.
4. The renderer takes `const Snapshot&`. It does not include `Simulation.h` internals beyond `ISimulation`.
5. Undo remains in the editor as the inverse of commands, or as a scene snapshot taken before the command. Do not also store undo inside the solver.

## What to consider

- A command applied twice (UI writes the field and also pushes a command) will double a drag. Pick one path. The command path is the one that survives a future sim thread.
- The queue is drained only at a defined point. Draining in the middle of ImGui layout makes the panel fight itself.
- `visual_body()` becomes "read object 0 from the snapshot" and can stay on the interface so old call sites compile during the move.

## Output

Dragging a location slider pushes a command. The cube moves after the next evaluate. The renderer has no non-const scene pointer. A test can push `SetTransform` without ImGui and see the snapshot change.
