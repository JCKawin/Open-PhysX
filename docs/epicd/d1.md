# D1 — Evaluate constraints, then modifiers, then physics

Points: 3. Epic D. Depends on the empty slots from [A3](../epica/a3.md). The real constraint math is [F2](../epicf/f2.md). The real modifier math is [E2](../epice/e2.md). This story is the order and the two meshes.

Blender spec: depsgraph object evaluation. Original ID versus evaluated copy.

## What to do

Each frame, for each object, in order: start from the authored transform and the original mesh, run the constraint stack, run the modifier stack, then let physics overwrite the world matrix of active rigid bodies. Store the result on an evaluated copy. Never write that result back into the original mesh or the authored transform, except for the physics write-back defined below.

## How to do

1. Add `EvaluatedObject` in `src/logic/`: world matrix, evaluated mesh id or an inline triangle list, and flags `constrained` and `simulated`.
2. `Simulation::evaluate()` walks objects. For each one:
   1. World matrix from parent chain and local transform ([A2](../epica/a2.md)).
   2. Constraint stack, when non-empty, replaces that matrix. Empty stack leaves it. Implementation of types is Epic F. The call site is here.
   3. Modifier stack reads the original mesh and the matrix and produces the evaluated mesh. Empty stack copies the original mesh id. Implementation of types is Epic E.
   4. Physics pass is a no-op function until [G4](../epicg/g4.md). The comment and the call order are this story. When it exists, active bodies replace the world matrix. Passive bodies keep the constrained matrix.
3. The renderer draws `EvaluatedObject`, not the authored mesh. The properties panel still shows the authored transform.
4. `demo_motion` moves to the evaluated position of object 0 only, as an extra draw offset, until [G4](../epicg/g4.md) removes it.

## What to consider

- Parent, then constraints, then modifiers, then physics. Swapping any two of those will not match Blender.
- A modifier that needs the original mesh (`RequiresOriginalData` in Blender) must see the unmodified positions. That only works if this function never aliases the output onto the input.
- Do not evaluate in `Workspace::draw`. Evaluate in `Simulation`, before render, on the sim side of the snapshot ([D2](d2.md)).

## Output

With empty stacks, the picture matches the pre-evaluation draw. A temporary test modifier that shifts vertices by `(1,0,0)` in the evaluated mesh leaves the original positions unchanged and moves only the drawing. Removing the test returns the picture. The properties panel never shows the shift.
