# D3 — Step cap and interpolation alpha

Points: 2. Epic D. Depends on [D2](d2.md). The solver can still be empty. The cap is on the loop in `Application.cpp`.

Blender spec: rigid-body substeps are inside one frame (`substeps_per_frame`). The display frame does not run an unbounded number of scene frames. `hardware.md` asks for a cap of 8 and an interpolation alpha.

## What to do

Stop the frame loop from calling `step` without limit after a hitch. Publish the leftover fraction of the fixed step so a later renderer can blend between snapshot N-1 and N. Do not blend yet if there is only a static scene. Store the alpha.

## How to do

1. In `Application::frame`, the loop is `while (accumulator >= 1/60) step`. After 8 steps, leave the extra time in the accumulator, or drop it down to one step of leftover. Dropping to `1/60` avoids a spiral. Document which one you picked in a comment next to the constant. Prefer clamp leftover to one `kFixedDt` so the next frame is real time, not debt.
2. `alpha = accumulator / kFixedDt` after the loop, in `0..1`. Store it on the simulation or return it from `step` bookkeeping. `ISimulation` can expose `interpolation_alpha() const`.
3. Eight is the display cap, not the rigid-body substep count. Substeps inside one simulation frame are [G2](../epicg/g2.md) and [G4](../epicg/g4.md). Do not confuse them.
4. Demo playback can still seek. Seeking is not the step loop. A seek evaluates once. It does not run the 8-step cap.

## What to consider

- The current loop is correct for a cheap sine. It will freeze the window when [G5](../epicg/g5.md) makes `step` expensive and a hitch tries to catch up forever.
- Alpha is meaningless if you drop the leftover and also set alpha from the clamped accumulator. Compute alpha before the clamp, or define alpha as 0 when you discard debt. Write the definition in the header.
- Do not start a sim thread in this story.

## Output

A test that feeds a 1 second frame dt calls `step` 8 times, not 60. `interpolation_alpha()` is in range. The cube demo still plays at the same speed when the frame time is about `1/60`.
