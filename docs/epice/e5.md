# E5 — Fluid modifier slot

Points: 2. Epic E. Depends on [E1](e1.md) and `FluidRole` from [A3](../epica/a3.md).

Blender spec: `MOD_fluid.cc`. The modifier is single. Its type is domain, flow, or effector. The solver is [H2](../epich/h2.md). This story only reserves the slot and refuses a second one.

## What to do

Add `ModifierType::Fluid` with a role field that mirrors `FluidRole`. Adding it sets the object's fluid role. Removing it sets the role back to `None`. Evaluation does not simulate. Cloth and soft body are not added.

## How to do

1. Payload: `FluidRole role`. Default `Flow` if you need a default, or `Domain` when the scene has no domain yet. Prefer: first fluid modifier in the scene becomes `Domain`, later ones become `Flow`.
2. One fluid modifier per object. One domain per scene. A second domain is refused with a status message.
3. The Modifiers tab shows the role as a combo: Domain, Flow, Effector. Changing it writes the command and the object's `FluidRole`.
4. `evaluate` sees the type and does nothing to the mesh. Domain does not hide the cube. The cube stays as the domain bounds visualization until [H1](../epich/h1.md) draws the bounds on purpose.
5. Do not add Cloth or Soft Body types. Their comment in the type enum, if you want one, says they wait on [G6](../epicg/g6.md).

## What to consider

- Keeping `FluidRole` on both the object and the modifier will drift. The modifier is the source. The object field is a cache copied during evaluate so the outliner can show an icon without walking modifiers. Update it only in evaluate or in the command, not in both with different values.
- An empty slot here is success. Do not stub a fake density grid.

## Output

The user can add one Fluid modifier, set Domain or Flow or Effector, undo it, and see the mesh unchanged. A second fluid modifier on the same object is refused. A second domain in the scene is refused.
