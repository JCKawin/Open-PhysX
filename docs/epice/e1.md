# E1 — Modifier list

Points: 3. Epic E. Depends on [A3](../epica/a3.md) and the Modifiers tab from [C3](../epicc/c3.md).

Blender spec: `ModifierData` in `DNA_modifier_types.h`. The list is doubly linked on the object. Flags include realtime (viewport) and render.

## What to do

Each object has an ordered modifier list the user can add to, remove from, reorder, and mute. One modifier is active. Edits are undoable. No modifier changes the mesh yet. That is [E2](e2.md).

## How to do

1. `ModifierHeader` in `src/core/`: `uint32_t id`, `std::string name`, `enum class ModifierType`, `bool show_viewport`, `bool show_render`, `bool active`. `ModifierType` starts with `None`.
2. The list is a `std::vector` in stack order, index 0 evaluated first. Do not use raw `next` pointers. Order is the vector order. Blender's linked list is the same idea.
3. Modifiers tab: Add, Remove, Up, Down. Up and Down swap with the neighbor. Add appends. The active row is highlighted. Viewport and render checkboxes write the flags.
4. Only one `active` flag is true. Clicking a row moves it.
5. Commands from [D2](../epicd/d2.md): `AddModifier`, `RemoveModifier`, `ReorderModifier`, `SetModifierFlag`. Each is one undo step.

## What to consider

- Render versus viewport flags both exist even though this app has one view. Render means "on when baking or exporting the evaluated mesh later". Viewport means "on in the window". Default both on.
- Names are `Displace`, `Displace.001` per object, not global.
- Do not evaluate in the panel. The panel writes commands.

## Output

The Modifiers tab on the active object can add three rows, reorder them, mute one, and undo each action. The viewport does not change, because nothing evaluates.
