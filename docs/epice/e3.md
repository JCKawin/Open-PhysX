# E3 — Displace or wave

Points: 2. Epic E. Depends on [E2](e2.md).

Blender spec: `MOD_displace.cc` or `MOD_wave.cc`. Either one proves the stack. Wave is the better demo because it uses time and shows the playhead.

## What to do

Add one deform modifier, Wave. It offsets vertex positions along their normals, or along Y if you want a simpler first version, using `sin(time + position)`. The original mesh does not move. Playback makes the surface move.

## How to do

1. `ModifierType::Wave` with fields on a payload struct: `float height`, `float speed`, `float width`. Default height `0.25`, speed `1`, width `1`.
2. `deform` writes `position += normal * height * sin(time * speed + dot(position, axis) / width)`. Use object-space positions from the working mesh, not world space.
3. The Modifiers tab shows the three fields when the active modifier is Wave. Editing them pushes a command and, later, will dirty the physics cache. For now it only dirties the evaluated mesh.
4. Normals are recomputed after the deform so lighting or a later collision read sees the wave. If you have no lighting, still recompute. [E4](e4.md) reads the mesh above it in the stack.
5. Object 0 can stay a primitive. Wave requires a mesh. Adding Wave to a box with no mesh does nothing and the row says "needs a mesh".

## What to consider

- This is `OnlyDeform`. Topology does not change. Index buffers are copied by reference or left untouched.
- `demo_motion` and Wave both move the picture. Turn the demo sine off when testing Wave so you can see which offset is which.
- Do not store the waved positions in the scene file. Store the modifier fields. Evaluation rebuilds the pose.

## Output

A meshed cube with a Wave modifier undulates while the timeline plays. The Object tab location stays still. Muting the modifier or undoing the add returns the rest mesh. A box with no mesh shows the "needs a mesh" note and does not crash.
