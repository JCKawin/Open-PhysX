# C1 — Move, rotate, and scale gizmos

Points: 5. Epic C. Depends on [A2](../epica/a2.md). Meshes from Epic B make the gizmo more obvious but are not required. The gizmo works on the primitive box.

Blender spec: `source/blender/windowmanager/gizmo`, `editors/space_view3d/view3d_gizmo_tool_generic.cc`.

## What to do

Draw a move, rotate, or scale gizmo on the active object. Dragging a handle runs the same transform operator as `G`, `R`, or `S`. The Tools radio buttons choose which gizmo is drawn. The keys still work and switch the tool.

## How to do

1. The gizmo is UI and renderer. It reads the active object's world position and the `View3D` basis (`view_right`, `view_up`, `view_forward`). It does not live in `logic/`.
2. Move: three axis arrows and a plane square, drawn as lines in the viewport overlay after the scene. Hit test in screen space. An axis is a thick line from the origin to the arrow tip. The plane handle sits between two axes.
3. Rotate: three rings. The ring facing the camera is the view-axis rotate, matching unconstrained `R`.
4. Scale: three axis stubs and a center uniform handle. The center matches unconstrained `S`.
5. On press, call the existing `begin_transform` path with the axis already set. On drag, feed that axis. On release, confirm. Esc cancels. Do not write a second transform implementation.
6. Screen scale: the gizmo is a constant pixel size (about 80 px). Convert pixels to world with the same `pixel_scale` the grab operator uses, so the gizmo does not grow as you zoom. Blender's gizmo stays a similar size on screen.
7. Draw it only for the active object, and only when that object is visible.

## What to consider

- Hit testing must happen before the viewport orbit. A right-button orbit stays the navigation chord. The gizmo uses the left button, which is also click-select. If the press hits a handle, do not also box-select.
- The gizmo origin is the world position, including the parent matrix from [A2](../epica/a2.md). It is not the local position if the object has a parent.
- Demo motion offsets the draw pose. The gizmo sits on the authored origin, or on the drawn origin, but not a mix. Use the drawn origin so the handle is on the cube the user sees. Apply the delta to the authored transform. That is the same split as `visual_body()`.
- Do not import Blender's gizmo runtime. Draw lines and test distances.

## Output

The Move tool shows arrows on the active cube. Dragging the green arrow moves it on Y only, and Ctrl+Z restores it. Rotate and Scale tools show their handles and call the same undo step as the keys. Orbit still works outside the handles.
