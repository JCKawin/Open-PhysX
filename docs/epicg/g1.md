# G1 — Frame arena and fixed-size pool

Points: 3. Epic G. Depends on [D2](../epicd/d2.md).

Blender spec: `BLI_memarena` (bump, free all at once) and `BLI_mempool` (fixed-size elements, stable addresses). Not `MEM_guardedalloc`. `hardware.md` already says `step()` does not call the global heap.

## What to do

Add two allocators in `src/core/`. The frame arena is a bump pointer rewound at the end of `step()`. The pool is a free-list of fixed-size slots for objects, constraints, and modifiers that must not move while the editor holds ids. `step()` allocates scratch from the arena only.

## How to do

1. `Arena`: one buffer, `alloc(size, align)`, `rewind()`. Alignment is at least 16. Default capacity 1 MB, grow by doubling only between frames, never inside `step()` after the first grow. A grow inside `step()` is a bug. Pre-size before the loop.
2. `Pool<T>`: slots of `sizeof(T)`, free list, `acquire()` / `release()`. Addresses stay valid until `release`. Iteration skips free slots.
3. Pair lists, contact manifolds, and island scratch in later stories allocate from the arena. Objects in the editor can stay in `std::vector` until a profiler says otherwise. The pool is for solver bodies that are created when a rigid body is validated and destroyed when it is removed. [G3](g3.md) is the first user. This story ships the allocators and a test.
4. Test: allocate 1000 ints from the arena, record a watermark, rewind, allocate again, and assert the second wave fits in the same buffer. Pool: acquire, release, acquire, and assert the address is reused. Assert `step()` on the demo scene does not call `::operator new`. The easy check is a counter the arena test owns, not a global malloc hook, unless you already have one.

## What to consider

- Rewind does not run destructors. Only trivially destructible scratch goes in the arena. Meshes do not.
- The pool must be copyable for the undo snapshot or the undo snapshot stores ids and rebuilds pool slots. Prefer the scene vector as the undo copy and the pool as solver-only runtime. Say that in the header so [G3](g3.md) does not put the editor object inside the pool.
- Do not replace every `std::vector` in the UI. This is the solver rule.

## Output

The arena and pool tests pass. `step()` of the current demo does not grow the arena. A comment on `ISimulation::step` states the rule. No rigid body exists yet.
