# G4 — Forward integrate, one frame at a time

Points: 5. Epic G. Depends on [G2](g2.md), [G3](g3.md), and [D3](../epicd/d3.md).

Blender spec: `BKE_rigidbody_do_simulation` in `blenkernel/intern/rigidbody.cc`. The solver runs only when time is the previous frame plus one. Substeps divide that frame. Kinematic objects are interpolated inside the substep loop.

## What to do

Replace the demo sine as the motion of an active rigid body. Each played frame integrates velocity under gravity with the world's substeps. The simulation does not jump ahead to an arbitrary time. Scrubbing forward into a hole does not catch up inside the draw. The sine offset is removed for objects that have a rigid body. It can remain for objects that do not.

## How to do

1. Runtime body in the pool: `Vec3 position`, `Quat rotation`, `Vec3 linear_velocity`, `Vec3 angular_velocity`. Seed them from the evaluated transform when the body is created or when the user moves it while paused.
2. On `step(dt)` while playing and not muted:
   - If `state.time` is at or before the start, reset `last_time` and the runtime bodies to the authored transforms. Return.
   - Let `frame_dt = 1/60` even if the display dt differs. The fixed step is the simulation frame. `Application` already calls `step(1/60)`.
   - `sub = frame_dt * time_scale / substeps`.
   - For each substep: kinematic and passive bodies copy the evaluated matrix (constraints already ran). Active dynamic bodies do `velocity += gravity * linear_factor * sub`, `position += velocity * sub`. Angular velocity stays `0` until [G5](g5.md) has contacts. Damping multiplies velocity by `exp(-damping * sub)`.
   - Write the runtime transform into the evaluated object for active bodies. Do not write the authored transform. The properties panel stays on the authored pose. Blender writes the simulated matrix onto the evaluated object. Match that.
3. If the user seeks more than one frame forward, do not loop `step` to fill the gap in this story. Leave the body where it was and set a status "cache miss" once [G6](g6.md) exists. Until then, seeking pauses the integration and snaps runtime bodies back to the authored pose. Say that in the status line so the snap is not a mystery.
4. Remove `demo_motion` from rigid bodies. Keep the checkbox for non-rigid objects.

## What to consider

- Y-up gravity from [G2](g2.md). The cube falls toward -Y, through the grid, because there is no floor yet. That is correct for this story.
- Substeps are inside the one `step(1/60)`. The display cap of 8 still limits how many `step` calls happen after a hitch.
- Do not allocate in the substep loop. The runtime body came from the pool. Scratch, if any, comes from the arena and is rewound after `step`.
- Axis locks multiply the corresponding velocity component by `linear_factor` or `angular_factor`.

## Output

Play drops an active cube under gravity, smoothly enough at 10 substeps that it does not tunnel through a later floor in one frame from rest at a few meters. A passive cube stays where the constraint stack put it. Seeking to the end snaps to the authored pose and the status line says why. Pause leaves the fallen evaluated pose on screen and the Object tab at the start location.
