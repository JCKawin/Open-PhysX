# G2 — Rigid body world

Points: 3. Epic G. Depends on [G1](g1.md).

Blender spec: `RigidBodyWorld` in `DNA_rigidbody_types.h`. Created by `BKE_rigidbody_create_world`. Defaults in `rigidbody.cc`: substeps per frame `10`.

## What to do

Put one `RigidBodyWorld` on the scene. It stores gravity, time scale, substeps per frame, solver iterations, a mute flag, and the last simulated time. The Physics tab edits these. Nothing steps yet.

## How to do

1. Fields, matching Blender's defaults where this project already has a number:
   - `Vec3 gravity` default `(0, -9.81, 0)`. Blender is Z-up and uses `(0, 0, -9.81)`. This project is Y-up. Gravity is -Y. Write that in the panel so nobody "fixes" it to -Z.
   - `float time_scale` default `1`.
   - `int substeps` default `10`, minimum `1`.
   - `int iterations` default `10`.
   - `bool mute` default false.
   - `float last_time` default `0`.
2. Physics tab, scene section, always visible. These are scene settings, not object settings. Blender puts them on the scene's rigid body world.
3. Save them in the scene file ([B2](../epicb/b2.md)).
4. Mute is a flag the stepper will read in [G4](g4.md). The panel can toggle it now.

## What to consider

- Substeps here are inside one simulation frame. The display cap of 8 from [D3](../epicd/d3.md) is outside. Both exist. A hitch does not multiply 8 by 10 on the UI thread beyond the cap. [G4](g4.md) defines the product.
- Do not allocate a Bullet world. The settings struct is the world until the solver exists.
- `last_time` is in the same seconds as `SimulationState::time`.

## Output

The Physics tab shows gravity, substeps `10`, iterations `10`, time scale, and mute. Changing gravity and reloading the scene file restores it. The cube does not fall.
