# B4 — PLY import and OBJ export

Points: 3. Epic B. Depends on [B3](b3.md).

Blender spec: `io/ply`, `io/wavefront_obj` exporter.

## What to do

Import a binary or ASCII PLY mesh the same way as OBJ. Export the original mesh of the active object as OBJ, in this project's Y-up coordinates, without the simulated or deformed pose.

## How to do

1. `src/io/PlyImport.cpp` reads the header (`element vertex`, `element face`, property names). Use `x y z`. Ignore color and custom properties in this story. Triangulate faces the same way as OBJ.
2. Apply the same axis conversion as [B3](b3.md) only when the user says the file is Z-up. Default PLY from this app is Y-up. Add a checkbox on the import. Default it off for PLY and on for OBJ/STL, and remember why in the dialog text.
3. `src/io/ObjExport.cpp` writes `v` and `f` from the original `Mesh`, one-based indices. Write positions in scene space of the mesh, not multiplied by the object matrix and not multiplied by a parent. Blender's "export selected" can include the object transform as an option. Default it off and name the option "Apply transform".
4. File → Export OBJ uses the active object. If it has no mesh, report that and write nothing.
5. Round-trip: export the built-in cube, import it with Z-up off, and compare positions within `1e-5`.

## What to consider

- Exporting the evaluated mesh would bake a wave modifier or a physics pose into the file. This story exports the original. Evaluated export is a later option, default off.
- PLY face layouts vary (`property list uchar int vertex_indices` is the common one). Reject a header you do not understand with the reason in the status line.
- Do not write normals into the OBJ. Recompute them on import. That avoids a second source of truth.

## Output

A PLY cube imports. Export OBJ of that object and import again yields the same positions when the axis option matches. A physics or modifier pose, once those exist, does not appear in the file.
